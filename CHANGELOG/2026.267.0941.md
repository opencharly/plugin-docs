# 2026.267.0941 — fix(docs): adopt spec v0.2026267.747 (mixed-tag-form resolver fix) + sdk v0.2026266.2340 + the docs-resolve R10 bed

## Summary

Adopt `spec v0.2026267.747` (the mixed-tag-form resolver fix from opencharly/spec#152) in the docs generator, with the compatible newer `sdk v0.2026266.2340`, and add the `docs-resolve` R10 bed that proves the resolution on a disposable target.

`plugin-docs` resolves `extra_repos`/`release_repos` through `refs.GitLatestTag` (`defaultRepoResolver`, `catalog.go`), so its resolution behaviour comes from its pinned `spec`. With the old pin it got the **stale** plain-form tag for a mixed-form repo — the generated `plugin-gh` page was frozen at `github-com-opencharly-plugin-gh-v2026-252-1501/`.

The `sdk` bump is required, not incidental: `spec v0.2026267.747` is incompatible with the old `sdk v0.2026254.439` (the old sdk's `kit/exec_aliases.go` references `exec.JumpPodmanExec`/`JumpDockerExec`, absent in the newer spec's exec surface), so the pair advances together. `v0.2026266.2340` is the newest `sdk` compatible with the fixed `spec` (verified by compiling the pair in a scratch module).

**Files changed:**
- `candy/plugin-docs/go.mod` / `go.sum` — the pin pair.
- `candy/plugin-docs/resolver_contract_test.go` (new) — a pin-sensitive unit test of the resolver.
- `charly.yml` (repo root) — adds the `docs-resolve-app` / `docs-resolve` R10 bed (the file was previously `discover:`-only).
- `candy/plugin-docs/testdata/bed-fixture/**` (new) — the bed's self-contained fixture: a minimal project declaring `extra_repos: [plugin-gh]`, its narrative sources + hand-authored pages, an astro config, and the candy's `testdata/marketplace` corpus. Resolving `plugin-gh`'s tags IS the network fetch under test.
