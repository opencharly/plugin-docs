# 2026.328.0705 — feat(generator): honour retired_skills in the candy-walk complement

## Summary

Part of opencharly/plugin-marketplace#64: the docs generator now honours the corpus's **retired skill cards**, the same datum the marketplace generator honours.

The corpus's retirement list carries individual cards as well as whole repos, because a card's thing can be consolidated or removed while its owner repo lives on — the node then survives only in the owner's OLD tags, and the candy-walk complement would hand it straight back to the site (the mechanism that resurrected `immich-ml` before opencharly/plugin-docs#27).

- `retired.go` reads `retired_skills: ["<family>/<name>", …]` with the same CLOSED-shape validation as the repo list; a malformed entry fails the run.
- `collectCandySkills` skips such a card wherever it comes from, before it can become a recipe card.
- The sdk pin advances to `v0.2026328.654` — the release that also honours a ref's **SUBPATH** (opencharly/sdk#628), so the stale whole-tree walks and the stale cards stop together.

**The dependency advance, named in full** (the bulk of the diff, all of it transitive from ONE module move):

- `github.com/opencharly/sdk` `v0.2026289.800 → v0.2026328.654` — the release that honours a ref's SUBPATH (opencharly/sdk#628). This is the change this PR is FOR.
- `github.com/opencharly/spec` `v0.2026289.611 → v0.2026327.605` — the version the SDK's own `go.mod` requires; MVS takes it.
