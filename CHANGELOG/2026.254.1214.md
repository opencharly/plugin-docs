# 2026.254.1214 — docs: Astro-safe path segments (sanitize dots/colons) — fixes the published 404 slug-mangling

## Summary

Fixes a live-site defect (RCA + verified published): Astro strips `.` and `:` from route slugs, so pages emitted under `github.com/opencharly/…:v2026.DDD.HHMM/…` paths served only under mangled slugs (`githubcom/.../plugin-checkv2026DDDHHMM/...`) — natural paths 404'd, breaking every generated link into the namespaced/versioned half of `reference/`.

- **One pure `sanitizeSegment`** (keep `[a-z0-9]`, replace the rest with `-`), applied at `entity.PathSegment()` AND at the landing-body site-link rewrite (`rewriteSiteAbsoluteDeepLinks` → `sanitizeSitePathSegments`) — so emitted file path == served URL == link target **by construction** (R3: one choke). Namespaces collapse into one sanitized segment exactly as pages are emitted; box/guide/concept/recipe paths are identity-unchanged.
- Transforms (verbatim): `github.com/opencharly/plugin-check:v2026.254.0445` → `github-com-opencharly-plugin-check-v2026-254-0445`; the `pod-sshd` Candy-reference rows in index/liberation now point at `github-com-opencharly-pod-sshd-v2026-239-1637/sshd/`.
