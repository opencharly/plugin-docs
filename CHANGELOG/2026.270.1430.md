# 2026.270.1430 — fix(docs)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Restore `plugin-docs`'s **own self-contained CUE schema** — the schema-less-plugin R5 cutover
tracked in **opencharly/charly#712** (the SDK contract landed as
**opencharly/sdk#314**). `NewMeta` passed a `nil` schema FS and served an **EMPTY**
schema — the SDK's former *"input-less plugin"* waiver. There is no schema-less plugin:
every plugin presents the same CUE declaration surface, even where a capability's authored
input is its pass-through CLI grammar (or a structured wire envelope) rather than an
authored `plugin_input`.

### Files

- `candy/plugin-docs/schema/docs.cue` — **NEW** (this PR): the plugin's self-contained schema (`#DocsPlugin`), documenting `command:docs`. It references no base def, so it compiles **standalone** and splices `base ++ plugin` at the host load gate (`charly/charly/plugin_loader.go` `registerPluginUnitSchema`).
- `candy/plugin-docs/plugin.go` — **modified**: `//go:embed schema/*.cue` + `sdk.NewMeta(calver, caps, schemaFS)` replaces the trailing `nil`; the stale comment (which claimed the capability carries no InputDef and the plugin `ships no CUE schema` (the candy/plugin-alias precedent)) is corrected in place.
- `candy/plugin-docs/docs_schema_serve_test.go` — **NEW** (this PR): `Describe` MUST serve a non-empty `schema_cue` carrying `#DocsPlugin` (fails without the change).
- `schema_splice_test.go` (alongside `candy/plugin-docs/schema/docs.cue`) — **NEW** (this PR): executes the REAL host gate (see §1; negative control §2).
- `candy/plugin-docs/go.mod` — **modified**: promotes `cuelang.org/go` from `// indirect` to a direct require (the new splice test imports `cuelang.org/go/cue` + `cuecontext`).
- `charly.yml` — **modified**: root schema stamp `2026.261.1747` → `2026.249.2125`, the max the repo's `deploy.yml` charly pin `v2026.258.0219` supports (the pre-existing RED `candy` CI; see §5).
