# 2026.256.1653 — fix: make the provider census and sibling indexes order-independent

fix: make the provider census and sibling indexes order-independent

## Root cause (R1)

`generateProviderIndex` sorted its rows on `(class, word)` with `sort.Slice` (unstable) and **no tiebreaker**. A word served by more than one plugin candy — normal, because the catalog documents every DEFINED version, e.g. `deploy` served by two `plugin-fleet` versions — left the relative order of those rows to the corpus **walk order**. Because the walk order shifts whenever any corpus pin changes, a one-line pin bump reshuffled ~36 unrelated rows of `reference/providers.md` and the committed tree stopped reproducing. The same non-total-key pattern sat in `gen_cli.go` (owners by Name) and `gen_recipes_index.go` (plugins by Name, cards by Name).

## Fix

Add the entity's unique page path as the final tiebreaker in each aggregate sort (`page` in the
provider index, `PathSegment()` in the CLI owners, `Dir()` in the recipe-index plugins). Output is
now a pure function of the entity SET, independent of walk order — the property the docs deploy
drift gate depends on. (The recipe-index *cards* sort needed no change: skill names are unique
within a plugin dir, so `Name` is already a total key.)
