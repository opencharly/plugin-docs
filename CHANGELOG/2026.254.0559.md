# 2026.254.0559 — docs generate: config-driven catalog view (single charly.yml docs node + compiled/release/extra feeds)

## Summary

Reworks the docs generator (command:docs, candy/plugin-docs) from a hardcoded file-walk into a **config-driven catalog view**, per the docs-generation architecture:

- **Config:** the generator reads the `docs:` node from the charly repo's `charly.yml` at `--root`, decoded with the **generated `spec.DocsConfig` types** (spec v0.2026254.503, the merged #DocsConfig contract). An absent node == all schema defaults (identical to prior behavior); an absent compiled manifest == empty compiled set; a present-but-malformed manifest still errors.
- **Catalog assembly (ONE assembly, R3):** the unioned entity set includes (a) the **compiled corpus** — read from the config's compiled_plugins path + go.mod path, each require mapped `v0.YYYYDDD.C → v2026.DDD.<C re-padded to 4>` (pure, tested) and fetched through the **same refs.DownloadRepo seam** as the @github closure, walked as remote entities with SourceRoot; (b) **release/extra repos from the config lists** via the same seam (go.mod pin if required, else latest CalVer tag); (c) the discovered/@github closure unchanged.
- **Emit:** existing emitters consume the unioned catalog; page shapes unchanged; placement still computed from compiled_plugins membership.
- **R5:** the old private resolution path (`compiledPlugins()` in sources.go) is DELETED — compiled plugins are no longer blind to the walk.
- **Defect fix (validator round 2):** `ensureVersions()` now runs before the release-repo loop, so a release/extra repo resolves from its go.mod pin even when the compiled corpus is disabled (was: latest-tag fallback). Regression test added: `TestAssembleCatalogPinsReleaseRepoWithCompiledDisabled` (RED on the pre-fix code — latest-tag fallback observed; GREEN after).
- **Defect fix (validator round 3):** an absent compiled manifest at the configured path resolves to the EMPTY compiled set at schema defaults (`os.IsNotExist` → `nil, nil`), so generation on a minimal checkout root works like the pre-config generator; locking tests for missing→empty and malformed→error.
- go.mod: spec → v0.2026254.503, sdk → v0.2026254.439.
