# 2026.328.0000 — fix(generator): resolve a file-sourced skill body in the candy-walk complement

## Summary

**Successor to opencharly/plugin-docs#30**, which the validator auto-closed at its five-verdict threshold; this is a clean PR from `main` carrying the whole change with every finding addressed. Closes opencharly/plugin-docs#28.

`collectCandySkills` read only the node's inline `content:`, so a moved candy whose body lives in `<repo>/.agents/skills/<name>/SKILL.md` projected a **BLANK recipe card** — and the module's `go test ./...` gate was red on `main` and on the released tag (`TestCollectCandySkills_ProjectsMovedCandySkill`).

The complement now:

- resolves the file through `candywalk.ReadSkillFile` — the SAME reader `collectSkills` uses — and **fills a missing body**;
- does **not** reconcile the two forms: refusing a disagreement is the AUTHORITY's check (the marketplace generator's `fillSkillFromFile`), and enforcing it here failed the live tree on description drift alone (`cuda-skill`, in the charly root manifest);
- **skips visibly** (a named stderr line per node) a node with neither an inline body nor a file — this complement is a fallback, and the corpus may carry the real body under the same name.
