# 2026.275.2127 — fix(docs): sanitize the CLI page path; lift the hero tagline from under the badges

## Summary

Two generator defects, both of which make the docs repo un-regenerable, plus the R10 witness
that catches each one. Both are in `candy/plugin-docs/` (the out-of-process `command:docs`
plugin, `charly docs generate`).

### 1. `fix(cli)` — the CLI page path was the one page-path producer that skipped the sanitizer

`reference/cli/<word>.md` was built from the **raw** command word. Every *link target* goes
through the same sanitizer, per segment (`sanitizeSitePathSegments`, `links_site.go:60`, which
calls `sanitizeSegment`, `sources.go:49`); this emitter did not. For the `noun:verb` spelling of a
nested command — `plugin-box` alone declares twelve of them today (`build:box`, `validate:box`,
`reconcile:box`, …) — it emitted a literal `reference/cli/build:box.md`, which Astro serves at the
slug-mangled `/reference/clibuildbox/`, while every generated natural link points at
`/reference/cli/build-box/` and 404s.

The failure is invisible in the file name and the sidebar never referenced those pages, so it
shipped: **19 colon-named pages are committed in the docs repo's `main` right now**, all of them
`:box` — measured on `opencharly/docs@origin/main`:

(The committed 19 is a **superset** of the twelve `plugin-box` declares today — `add-candy:box`,
`cat:box`, `fetch:box`, `refresh:box`, `rm-candy:box`, `set:box` and `write:box` are no longer

The fix restores the invariant the sanitizer exists to make true *by construction* — **page path

Every *dynamic* producer routes through `entity.PathSegment()` (`sources.go:74`, which sanitizes)
or a fixed literal (`recipes/index.md`, `vision.md`, …). This was the single dynamic producer that
built its path from a **raw source string** — and opencharly/plugin-docs#7, which introduced
`sanitizeSegment` and stated the invariant holds "by construction", missed it, which is why the 19
pages above shipped.

The word keeps its raw `noun:verb` spelling in the page title and prose; only the **path** is
sanitized. `TestGenerateCLIPagePathIsSanitized` asserts the **pair** (the sanitized page exists
*and* the raw page does not), so a future regression cannot pass by asserting one side.

### 2. `fix(landing)` — the hero tagline was anchored to the line directly after the H1

`liftLandingTagline` matched `\A\*\*…\*\*\n\n` on the body with the H1 stripped, i.e. it required
the tagline to be the **very next line**. A badge line in the hero therefore made
`charly docs generate` **hard-fail** with `no tagline found` on a README that plainly has one —
and because `landingTaglinePattern` is deliberately position-anchored (a first-match search would
hoist the bridge paragraph into the hero), the failure was total, not a wrong pick.

opencharly/charly#750 put two badges under the H1. That blocked **every** docs regeneration at any charly pin
at or after it.

`splitLandingBadges` steps over leading badge lines (markdown image, optionally link-wrapped, or
HTML `<img>` / `<a><img></a>`) and anchors the *existing* pattern to the first line that is not a
badge. Badges are **kept in the body** — only the tagline is lifted, because the hero renders it
from the frontmatter — and `splitLandingBadges`'s two halves concatenate back to its input, so no
content is dropped. The position anchoring that stops a later bold-opening paragraph being hoisted
into the hero is preserved: the badge scan stops at the first non-badge line.

### 3. `test(bed)` — `docs-resolve` now witnesses all three generator paths

The bed witnessed **one** generator path (`origin/main`'s header: "WHY THIS BED EXISTS." singular —
the `extra_repos`/`release_repos` tag-form resolution, 2 plan steps). Its header now reads
"the R10 witness for **THREE** generator paths", and it carries **4** plan steps, because this PR
adds the witness for each path it fixes:

- **the tag-form resolution** (`docs-resolve-generate` + `docs-resolve-tag`) — as before;
- **the landing projection** (`docs-resolve-tagline`) — the fixture README carries two badge lines
  between its H1 and its tagline, the shape that used to hard-fail the projection; the step asserts
  the tagline is lifted from **under** them, both badges are **kept** in the body, and the tagline
  is not also left behind in it;
- **the CLI page path** (`docs-resolve-cli-slug`) — the fixture project resolves `plugin-box`, the
  candy that declares the twelve `command:<verb>:box` words, through `extra_repos`, and the
  fixture's hand-authored start page links to one of them **at the sanitized spelling**
  (`/reference/cli/build-box/`). The page path the emitter writes and the link target the site
  resolves must agree, so the fixture's **own link gate** goes red on the raw-path regression and
  green once the emitter sanitizes; the fourth step then names the page-path pair directly, so the
  failure names itself instead of surfacing only as a dangling link.

A fixture with no colon-carrying command word does not exercise that path at all, which is why
`plugin-box` was added to `extra_repos` rather than left out.

No public API changes. `charly.yml`, the candy entity and `schema/docs.cue` are unchanged in
behaviour; the manifest edits are the bed's plan (a fourth step), its prose header, and the
prose sweep below.
