# 2026.327.1807 — fix(generator): honour the corpus's retirement list in the candy-walk complement

## Summary

The docs generator now honours the corpus's **retirement list**, closing opencharly/plugin-docs#27.

`generate()` merges the corpus's skills with the candy `skill:` entities a remote-aware walk collects (`collectCandySkills`), keeping the corpus's copy when both exist and the walk's when the corpus lacks it. A skill the corpus has **retired** is absent from the corpus by definition, so the walk always won it back: after opencharly/marketplace#644 retired `pod-immich-ml`, this generator still wrote `recipes/immich/immich-ml.md` from the retired tree — reached through the stale subpath pins opencharly/plugin-marketplace#63 measured.

The policy is data in ONE place, `retired.cue` at the corpus root, and `--plugins` already names that checkout:

- `retired.go` reads and validates it against the same CLOSED shape the generator's `#Retired` defines (three lines, restated here because this module must not depend on the marketplace plugin). A missing list is a no-op; a malformed one is fatal, never "nothing retired".
- `collectCandySkills` skips every entity whose fetched export tree is a retired repo (`Entity.SourceRoot`); a local entity is never retired by a repo list.
