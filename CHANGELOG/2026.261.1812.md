# 2026.261.1812 — fix(docs): dedupe the corpus and walked skill collections

## Summary of changes

Three coupled fixes in the docs generator and its `candy` CI, all in one repo:
the duplicate-skill dedupe that `opencharly/docs#125` surfaced, the module's lint debt, and the `candy` gate that has been red on `main` since 2026-09-13.

**1. Dedupe the two skill collections (the real defect).** `collectSkills` (the marketplace-corpus read) and `collectCandySkills` (the walked candy projection) both fed the same `skills` slice with no dedupe, so the same card reached `generateRecipesIndex` 2–3 times and `recipes/index.md` listed it as repeated bullets for one page. `generateSkills` wrote one file per path either way, so the defect was visible only in the index listing.
- `candy/plugin-docs/gen_skills.go` — new `skillKey` (`family/name`, the same two segments `skillPagePath` uses) and `dedupeSkills(corpus, walked)`: keeps the **first** occurrence per key, so the corpus copy wins and the walk contributes only skills the corpus lacks.
- `candy/plugin-docs/generate.go` — the assembly calls `dedupeSkills(skills, collectCandySkills(rawEnts))` instead of an unfiltered `append`.

**Why corpus-wins is the correct precedence:** the marketplace corpus IS the published projection of each candy's `skill:` entity (`charly marketplace generate` produces it). The walk's documented purpose is the *complement* — a moved candy whose regeneration has not landed, whose reference would otherwise dangle. The old unfiltered append also let a walked copy silently **overwrite** the corpus copy of every shared card.

**2. Clear the module's 5 lint findings** so `golangci-lint run ./...` is green: an unchecked `f.Close` and an unused `copyFile` helper (`generate_test.go`), two `QF1001` De Morgan hints and one `QF1008` embedded-selector hint (`paths_test.go`).

**3. Repair the `candy` gate.** It has failed on `main` since 2026-09-13 — not on the manifest, but on its own pinned charly: `v2026.238.1242` predates the `docs:` kind, so `charly box validate` cannot parse the hermetic fixture `candy/plugin-docs/testdata/project/charly.yml` (`node "docs": no kind discriminator`). Bump the CI pin to `v2026.258.0219` (carries the kind) and stamp the two manifests the current schema requires (`charly.yml` and the fixture, which had no `version:` line) at `2026.249.2125`.

**Closes / relates to:** `opencharly/docs#125` (the regeneration that surfaced item 1). Item 3 is a pre-existing red required-adjacent gate fixed in-tree.

**Breaking change + rollback:** `none` for item 1 — the emitted *page set* is unchanged (one file per path either way); only the index listing and which source's text wins per shared card change. Items 2–3 are test/CI/manifest-stamp only. Revert the merge to roll back.
