# 2026.237.2328 — feat: the docs generator discovers the candy corpus through remote refs (the candy cutover Phase 3)

## Summary

The candy de-submodule cutover, Phase 3: the docs generator becomes FULLY ref-driven. Three changes:

1. **Remote-ref discovery** (`sources.go`): `walkRemote()` is the ONE shared remote-aware walk (`candywalk.CollectEntitiesRemote` with `spec/refs.DownloadRepo` — the standalone fetch the runtime uses). `generate()` walks ONCE and feeds both projections via `collectEntitiesFrom` (candy/box) and `collectCandySkills` (skill cards) from the same slice (R3 — the walk executes exactly once; the single-walk fix halved the full-suite runtime 396s → 196s). A moved candy's entity carries `SourceRoot` = the fetched repo tree, so `collectPlugins` reads `schema/` from there.

2. **Candy-skill projection** (`gen_skills.go`): the R1 divergence the Phase-3 RDD surfaced — the docs generator's skill corpus came ONLY from the marketplace projection, which is STALE after the candy moves (the marketplace repo at main predates the cutover). A moved candy's `skill:` entity lives in its standalone repo, so `collectCandySkills` projects skill cards + reference files from the SAME remote-aware walk (family → plugin dir, content → body, references → reference pages, agent-type routed to the marketplace agents/ emission).

3. **Test-layout fix** (the standalone layout broke the in-repo assumptions): `superprojectRoot` resolves the charly SUBMODULE checkout; `marketplaceCorpusDir` resolves the corpus via env override (`CHARLY_DOCS_MARKETPLACE` — the RDD bed regenerates into a temp dir) → in-repo → `refs.DownloadRepo` fetch, and the wiring tests RUN IN FULL (no skip).

**Dependency pins:** `github.com/opencharly/sdk` → `v0.2026237.1545-0.20260825162141-24eba1a516c5` (the candywalk remote-mode `CollectEntitiesRemote` — the sdk#167 landing) and `github.com/opencharly/spec` → `v0.2026232.521-0.20260824192047-0c29ab15816d` (the `refs.DownloadRepo` / `spec.Skill` surface both new code paths import).

The marketplace repo at main stays stale until the marketplace regeneration lands (the companion plugin-marketplace PR + a regeneration run) — the tests run against the regenerated corpus via the env override.
